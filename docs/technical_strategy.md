# 技术路线：面向最终能力，分阶段建立闭环

用户确定：**PWM 是主控制路线**。目标是在比赛允许的传感器和运行条件下，建立能够适应不同场景、完成六段飞行及工厂巡检的自主系统。先解决小任务是验证最终架构的方式，不是把目标缩成一个演示。2027 规则和正式接口须重新核实。

PWM 提供直接控制电机的自由度，是本项目追求高动态控制和深入优化的长期选择；但自由度本身不证明当前 PWM 实现的成绩、安全性或鲁棒性一定优于 VEL。它的实际收益要在同场景独立对照中测量。VEL 仅用作独立场次的接口、物理响应或故障定位对照，不替代 PWM 主线，不与 PWM 同场混发。

## 目标架构与依赖

```text
传感器 → 状态估计与不确定度 ─┐
                            ├→ 世界模型 → 任务与轨迹规划
视觉/雷达 → 几何与动态感知 ──┘                 ↓
                                  可行性/净空/制动校验
                                               ↓
                           轨迹跟踪 → 姿态控制 → 混控 → PWM
                                               ↓
                            运行监测、降级与有界恢复
```

坐标、时钟、输入权限、数据年龄和失效语义贯穿各层。先定义共享接口和可观测量，单独验证模块，再让同一条 PWM 闭环逐步执行更复杂任务。先做简化场景并不意味着用临时代码替换最终架构：简化假设、缺失能力、退出条件都须写明。

## 开发顺序

1. **基线与物理可观测性**：恢复原模拟器/ROS 环境，冻结版本；厘清时间、坐标、PWM 通路和可用传感器。先记录真实控制行为及不确定性，定位偶发冲击。
2. **PWM 基础闭环**：IMU/GPS 状态估计 → 位置/姿态跟踪 → PWM；分级验证悬停、小位移、不同方向速度、制动和有限扰动恢复。持续失联处理单列，不把宿主停止仿真当比赛回退。
3. **PWM + 本轮感知**：在线观测首门，统一时间和坐标，结合地图与规划生成短轨迹，低速完成第一门；保留后续扩展到多门、动态障碍和工厂的接口。
4. **连续与泛化**：多门、完整第一段、跨种子、动态车辆和线障；冻结配置评估成功率、时间、最小净空和失败类型。
5. **工厂与全赛程**：GPS 不可用下的定位、设备识别、读表及确认上报，逐项接入 PWM 主链，最后进行全程与性能验证。

不同方向可以有限并行，但每项工作须标明它消除哪个已知依赖或验证哪个后续风险；主链进度以真实闭环和阶段结果衡量。暂不要求所有研究等前序阶段完成，但不得用单项离线成果冒充整机进展。

## 优先要做的技术决策

- **PWM 异常**：先复现并分离控制指令、状态估计、模拟器桥接/执行与场景影响。现有插桩显示存活期和并发疑点，尚未证明冲击因果；不得把改动模拟器的诊断结果当正式修复。实验须记录未插桩原环境及控制输入，必要时使用独立 VEL 场次作对照。
- **控制性能**：针对悬停、位移、制动和恢复预先定义可量化的成功标准；以实测误差、峰值、成功率、保护触发与命令时效建立包络。先小范围辨识，再扩大速度和扰动；阈值根据物理需求与基线数据明确设定，不事后为了通过而调整。
- **状态估计**：以比赛可用输入为准建立 IMU/GPS 基线，真值只作隔离评估；将无 GPS 视觉/惯性作为后续必需能力研发，并通过场景回放、标定和实时性逐步进入主链。不要因首门在室外就忽视工厂需求，也不要求未验收的 VIO 阻塞室外估计验证。
- **实时感知与规划**：测量从采样到执行的时延、时钟一致性和可用覆盖，依据速度、净空、制动能力评估预算；不能只为让数据通过而放宽有效期。在线轨迹要同时满足运动学和地图语义，并验证机体实际执行。

# 比赛优先：轻量验收标准（2026-10-30 起生效）

背景：原 [flight_milestones.md](flight_milestones.md) 的验收标准导致迭代周期过长。即日起比赛线按本文件执行；原标准保留，仅用于赛前最终复核与对外提交。

## 总原则

1. **完成率优先**：目标是"能跑完、能得分"。根因不明的已知风险用"失败场自动重跑"消化，**不以根因证据作为推进前置**。
2. **每轮只留一份简短记录**（改了什么/得分表变化/风险清单更新），不再逐项写证据文档；完整证据仅对最终提交配置补做。
3. 每轮必须产出**得分表**：固定开发 seed 集（123/456/789/42/2026）的 分数/到第几段/用时/失败点/失败原因。只有能改善得分表的改动才算有效迭代。
4. 失败场自动重跑 ≤2 次，仍失败则记录风险清单并继续，不阻塞。

## 分级验收（轻量）

- **M0**：环境可重复启动 + 1 场 PWM 有界悬停成功即通过。清理失败记录后重试。
- **M1**：连续 3 场中 ≥2 场完成有界悬停且无安全边界突破即通过。偶发角速度异常计入已知风险清单即可；**不再要求根因或经验证的风险边界**。
- **M2**：低速往返 + 制动 2 场完成即通过，误差只记录不设硬阈值。
- **M3**：官方/HUD 第一门通过事件 ≥2 次（共 5 场）即通过。不要求感知全链路 150ms 合规，先端到端跑通；**优先 SGBM/几何方案，学习立体非必需**。
- **M4**：开发 seed 123 与 42 各 ≥1 次跑完 1→3 段即通过；留出种子仅赛前 3 天复核。
- **M5**：动态段用保守停等/绕行通过 1 次即算初版；工厂任务只做最低限读表上报。
- **P7 性能**：全部阶段结束后再做。

## 时间盒

M1 ≤1 天、M2 ≤1 天、M3 ≤2 天、M4 ≤3 天。超时即砍范围（可复用 beta 模块）并记录，不等验收完美。

## 不变的安全与合规底线

- 不修改官方模拟器、碰撞或计时设置；不以 HUD 数字冒充正式验收。
- 保留既有飞行安全边界，不为进度放宽。
- 真值仅用于事后评估，不进入控制回路。

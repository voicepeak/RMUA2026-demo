# 2026-09-30：速度、3 号窗口、计时与返程

用户确认后续流程是 3 号终点掉头，沿 3 号路回枢纽，再去 5 号终点。返程计分门位置不变，新增悬浮汽车；`Finished` 不应被解释为整场已完成。

## 已查明的问题与修复

- **未计时**：e8 模拟器开始运行到控制器初始化约 41 秒，超过 30 秒出发窗口。旧轮次界面显示 `Time:0 / State:Finished`，但穿门仍会增加 Score。重新启动并自动及时出发后，fast_f2 界面明确显示 `State1 / Time:32.017`。仅调用机体 reset 不能当作新比赛。
- **下降慢**：原下降表为 3 m/s，预览还有 eta 和响应时间折减。fast_f2 采用单独实验能力表（下降 4.5 m/s，实际命令最高约 3.67 m/s），s1050–1250 水平速度中位数从 e8 的 4.50 提高到 7.49 m/s。95% 高度跟踪误差约 1.34 m；此表是经过路线验证的实验配置，并非完整动力学校准。
- **窗口擦边**：原枢纽外推高度 s750–840 约 -136 至 -137 m，实际返程穿 3 号窗口高度约 -134.5 m。已经用这次观测修正 seed123 的枢纽高度指导。fast_f2 在 s780–860 只有 5 帧被避障限速，e8 为 56 帧。
- **停车后不能横移**：原横向命令也被前进速度上限压为零。现在只有新鲜雷达确认存在满足净空的候选时，才允许最高 1.5 m/s 的独立横移，并保留加速度限制；无可用候选、过期点云均不授权横移。
- **返程**：启动时先原地转向；重新计算门法向，复用去程高度轨迹，重启视觉以加载当前方向的路线。修正调度器错误的 `route_name:=` 参数为 launch 支持的 `route:=`。
- **启动空终点**：模拟器初始化时会短暂发布 `(0,0,0)` 目标；调度器忽略与当前预期道路不匹配的初始目标，避免误切阶段并杀死正在起跑的控制器。
- **雷达避障边界**：横移候选限制在 ±3 m、高度修正在 ±1.5 m，并按前方距离加入制动限速。堵塞持续时发布 `PERCEPTION_REQUIRED`，原因 `NO_SAFE_LIDAR_CORRIDOR`。

## 一键启动（固定 seed123）

先同步运行源文件：

```bash
rsync -rt --exclude=__pycache__ repo/ros_ws/src/route_follower/ rmua_ws/src/route_follower/
python3 repo/tools/start_seed123_race.py --mode render
```

启动器自动完成旧模拟器清理、容器重启、及时启动控制器、并行加载视觉、记录轨迹，以及监听正式目标切换。不要先启动模拟器再花较长时间加载视觉和手动输入控制命令。

`--continue-on-route-end` 仅用于用户授权的本地路线调试，明确记录官方完成状态 UNKNOWN；正式启动器默认不使用它。工厂巡检尚未实现，调度器不会猜测仪表数值。

验证：137 项单元测试通过；Python 编译与 `git diff --check` 通过。

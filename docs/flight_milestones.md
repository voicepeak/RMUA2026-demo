# PWM 主线：飞行里程碑与验收

大目标和架构见 [技术路线](technical_strategy.md)。各阶段沿同一 PWM 主链推进；当前描述是计划，尚非验收结果。先恢复环境，再在受控场景逐步扩大范围。每次先固定验收阈值与实验协议，依据比赛几何、物理能力和已有基线确定；缺少依据时先测量，不编造数值或事后调整。

## M0：可复现基线与可观测性

恢复 Linux/ROS Noetic、模拟器、GPU 与控制环境；核对代码、运行副本、模拟器/配置哈希、ROS 类型、时钟及输入来源。复现 main 的 PWM 有界实验并记录成功、故障及环境异常；beta 可作为历史对照但不是主线前置条件。

**退出条件**：能重复启动/清理同一受控实验并保存版本、指令、状态及诊断数据；明确缺失观测和控制接口。实验不隐瞒 PWM 偶发冲击。

## M1：PWM 稳定悬停及失效边界

使用正式可用候选输入建立状态估计与 PWM 闭环，先低高度悬停，逐级验证有限扰动、状态过期及停止条件。复现与定位偶发角速度异常；可用独立 VEL 场次和离线真值诊断，不能用修改过的模拟器或真值控制来冒充验收。

**退出条件**：预先冻结的重复试验达到事先约定的悬停误差、姿态/角速度、指令时效及安全条件；所有保护触发和失败计入。若根因仍不明，必须有经验证的风险边界和恢复策略，才可在其范围内进入下一阶段；未知风险不得被描述为已修复。持续 IMU 失联和自主回退须单列，不用关闭模拟器冒充比赛安全策略。

## M2：PWM 位置跟踪与制动

在同一主链上，从小位移到多方向低速运动，测量轨迹跟踪误差、速度、制动距离、控制饱和和恢复；用独立真值只做事后评估。

**退出条件**：冻结协议下重复完成运动与制动，满足事先定义的误差、净空、时效和保护界限；输出在后续规划中可使用、注明适用范围的能力边界。

## M3：在线通过第一扇门

固定开发 seed，不加载历史预录门图或高度指导；使用本场允许输入、在线门感知、状态估计、规划和 PWM 跟踪自主起飞并穿门。记录坐标、输入年龄、轨迹、安全判定和实际运动。

**退出条件**：按预先规定重复试验，保存源码配置、观测与控制记录；有可核验的官方门触发/得分事件，核对碰撞和超时。若官方事件不可用，记录 HUD/本地轨迹为候选进展，不宣称正式验收。开发用真值或历史地图只作对照，不作为通过证据。

## M4：连续门、第一段与跨种子

同一 PWM 链路连续穿门，完成 `1→3` 的官方阶段切换；之后冻结代码、配置、模型及评价协议，使用开发种子和未参与调参的留出种子多次运行。报告全部结果、成功率、用时和主要失败，不按 seed 添加预录路线或调参。

## M5：动态障碍、工厂与完整赛程

逐步验证动态车辆、线障、风与前三段；再验证无 GPS 定位、工厂设备识别、读表上报及六段连续任务。明确每项正式接口和事件，最后开展性能优化。视觉惯性、动态障碍和读表可为降低风险而并行预研，但须有清晰交付和依赖，不替代前述 PWM 闭环验收。

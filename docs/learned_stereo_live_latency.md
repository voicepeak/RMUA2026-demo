# 学习双目在线时效实验（2026-10-23，迭代 35）

按设计第 13 节，在真实运行的官方模拟器旁启动独立 GPU 进程，测量正式图像到诊断视差返回的链路。结果未达到 150ms 默认预算或 200ms 实验预算；全部结果按原始 lease 拒绝，尚无可供控制使用的在线深度。规则、原始模拟器/插件/配置核对沿用 [官方要求](official_rules_review.md)，没有关闭碰撞/超时或启用 RPC。

算法、权重、0.5 输入缩放/4 次迭代/192 模型像素/FP16、原图 1px 左右一致性和双侧纹理门限与 [迭代 34](learned_stereo_comparison.md) 相同。模型进程只接收正式前视双目 RGB 与来源元数据，不接触 LiDAR、位姿、真值、debug 或场景对象。只读 ROS 节点仅订阅 front_left/Scene、front_right/Scene、IMU；ROS 图核对仅有 `/rosout` 发布。

Noetic 的图像/IMU 接收与推理分开：每侧原始消息保持最新一条，配对缓冲每侧 4 条、原始载荷索引每侧 8 条；推理至多一个处理中、一个待处理。新配对只替换等待项，不能修改已交付的输入。发送前、序列化后、结果收到并校验后分别检查时效。IPC 使用有界 JSON/字节协议，不用 pickle，图像 4,147,200 bytes，返回原图 float32 视差及 uint8 掩码 3,456,000 bytes。检查请求序号、输入/输出 SHA、来源元数据，保留 NaN/UNKNOWN。异常、时钟失鲜/回退、换 epoch、来源过期和 wall 过期都不能授予时效通过。

原图 stamp、valid_until、epoch 直接带到结果。时效通过仍不等于几何已标定或允许控制，本实验所有输出都保持 diagnostic-only。曝光时间未知，因此以下是图像头/IMU 时钟与回调/单调时钟两种年龄，不是曝光到执行器的总延迟。

200ms 场次另有每侧 55 条过期配对缓存项，150ms 场次左右分别 160/161 条。没有本地 pending 覆盖，实际也没有 latest-slot 替换；队列不会增长及替换只影响等待项另由压力单测验证。ROS/驱动层丢弃数未知，原始记录仍声明有损，不能把本地覆盖为零当成零丢帧。GPU 请求约 2.8/s 和 0.1/s 只描述各自选择窗口；两种 TTL 使用不同开发场次，不能单独据此推断 TTL 的因果效应。

同一 GPU0 上可观察到 C-FFS Python CUDA 进程与模拟器 C+G 进程。每约 0.5s 独立采样一次 GPU 和系统 CPU：200ms 场次 GPU 利用率中位数 66%、采样峰值 100%，总 GPU 内存采样峰值 2,266MiB；另一个场次 GPU 峰值 69%。CUDA 模型分配器峰值 allocated/reserved 为 469,507,584 / 580,911,104 bytes。GPU 总量包含模拟器/驱动，采样可能漏掉峰值；系统 CPU 统计为所有核心总忙比例，不能归因给算法。Noetic/GPU 进程最大 RSS 和全部采样随运行保存。

IMU 回调间隔最大约 14.09/14.97ms，记录数 1000/999。该观测没有运行 ESKF、控制器或规划器，不证明 100Hz 控制最坏时延。GPU 在场景启动前加载、使用零图预热，有已有编译缓存；启动记录不证明比赛冷启动、30s 出发或部署镜像达标。与上轮独占 GPU 的计算耗时相比，本场同时包含不同输入、资源负载和 IPC，不能将全部差异归因于 GPU 争用。

每份结果独立重核原始来源 TTL、epoch、IMU 记录、跨进程单调时间顺序、时效拒绝原因和请求/响应一致性；两场首对图像与 cv_bridge 的 RGB 解码逐像素相同，原始载荷与输入/返回掩码摘要匹配。结果字节回传与接收端验证都包含在在线测量中，首份载荷归档放在结果检查之后。没有修改模拟器二进制、插件或官方配置。

# 静态轨迹连续扫掠核验（迭代 41）

2026-10-24。按设计 6.1、11.3，实现地图到规划的静态几何检查接口。开始前重读设计与官方约束，并核对今日已重新下载的官方两份 PDF/README 摘要记录；规则基线一致。本轮不启动模拟器或发布控制。

`planning.trajectory_validator.static_sweep.check_static_sweep` 直接消费现有
`Trajectory`、`OccupancySnapshot`、时刻/epoch 和显式 `SweepBounds`。后续规划器可以用它
拒绝穿过占据、未知或过期区域的候选轨迹；当前没有把它接到 PWM 发布，也未放行实际飞行。

- 检查当前时刻至轨迹终点的连续空间，而非只查离散采样点。线段与按机体包络膨胀的体素用 slab 区间求交，擦碰边界也拒绝。
- world_ned 轴向盒必须覆盖允许姿态下的完整机体/旋翼，调用方必须显式提供尺寸。测试中的小盒是合成对象，不是本机无人机尺寸。
- 加入跟踪偏差和 `a_max * sample_dt² / 8` 膨胀，包住满足连续加速度上界的采样间弯曲参考。仅采样加速度符合不能证明整个区间的上界；规划器必须提供该保证。裁剪旧轨迹前缀不缩小原采样间隔的偏离界。
- 地图须覆盖整个检查时域，每个 FREE 体素须有当前已存在、同 frame/epoch 且覆盖接触区间的证据；不会提前使用未来观测或延长原 lease。已离开体素随后过期不必否决后续轨迹。
- 分段、地图规模和候选体素检查数均有上限；预算耗尽或数值范围异常返回拒绝，不能把部分检查当成通过。浮点边界向外膨胀。

`clear=True` 的含义仅是“在给定包络、偏差、连续加速度和静态地图假设下空间可用”。
它不证明地图/包络已标定，也不检查动态对象、道路/力场、制动能力、状态健康或控制可达性。
现有 LiDAR 端点图仍是传感器 frame 且没有 FREE，不能直接据此放行飞行。

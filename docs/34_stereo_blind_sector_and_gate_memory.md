# 车辆下方盲区与门位置记忆修复（2026-10-12）

## 复现依据

`latest_visible_20261012_02` 使用 main c2a7f1a 的完整接线配置，第一阶段通过官方终点变化确认完成（152.369秒）。车辆阶段 HUD 到101分后结束，最后有效进度894.503米；不能将101分计为车辆阶段通过。800–820米段约3.65秒，已有间隙改进有效，但101分附近的碰车仍未解决。

MID360 的机体向下视场仅7°，最后几秒下降轨迹比这个视场更陡。883米、890米冻结点云表明规划轨迹通过了当时的 LiDAR 检查；近车进入新点云时才发出退避。增加0.6–1秒历史点云没有充分覆盖这辆车。同步双目检测图的初步重放能补充轨迹下方障碍，但带标注图的结果只是诊断证据，不能等同原始图或实飞验收。

609–894米没有后续可信门。现有控制器与视觉通过 `/airsim_node/drone_1/debug/pose_gt` 使用世界位置和姿态，已有世界坐标门地图；`/airsim_node/drone_1/gps` 为 PoseStamped，本轮未替换定位话题。已知道路可以在门暂时不可见时继续提供方向和高度先验；位置本身不能产生尚未测量的门或证明障碍空闲。

## 实现

- 车辆段启用 `lidar_stereo_obstacles`。双目在机体下方7°以外提取0.8–20米的占据点，用图像曝光时的位姿转换到世界坐标。三乘三邻域支持和视差中值一致性筛除孤立匹配。
- `ObstacleCloudFusion` 保留全部原始 LiDAR 点，加上不超过0.6秒的相机占据点。空图像不清除旧障碍；空 LiDAR 不允许被相机替代。规划和发布前复核使用同一融合规则；新相机数据到达时，即使 LiDAR 时间戳未变也重建索引。移动物体速度估计仍只使用原始 LiDAR 帧。
- 已经测得立体几何的门不会再被后续单目框大小造成的距离跳变搬走。首次有效几何替换旧框中心估计，几何测量不确定度参与可信门条件与可用开口尺寸。
- 车辆视觉增加橙白门框候选；OpenCV 补充候选必须通过有效立体四边形几何，不进入普通框深度回退。仅有矩形检测框时不把其平面法向当成实测门倾斜。
- 地图发布使用现有道路横向距离过滤。道路高度先验和可信门的观察范围分开记录。没有后续门时进入 RECON，已知道路上限10米/秒，搜索距离有限且以该段道路长度为限；高度模型继续保留原有不确定度限制。
- `latest_visible_20261012_03` 第一阶段在终点前约25米停住。冻结点云最近门侧约0.76米，1.25米缓冲不可能满足；启用终点局部0.75米静态余量后，完整响应检查得到 LIDAR_TRACK。`lidar_terminal_margin` 仅在耦合控制的终点接近区生效，默认关闭；动态占据仍需1.25米余量，离开终点区恢复原配置。第一阶段耦合启动接线启用该参数。
- 实验快照额外保存视觉源文件及 SHA256，避免只记录控制器而遗漏感知改动。

## 当前验证范围

容器内542项测试通过；冻结终点点云复现原策略阻塞与新策略可行指令。控制器构造检查、运行源码同步检查已通过。保留几何的离线门地图重放仍未恢复609米后的新可信门，因此尚不能声称解决下一个门的识别。

实飞与正式阶段通过情况需以新轮 HUD、最后有效遥测及官方终点变化为准。单元测试和局部冻结点云结果均不代替车辆段验收。

## 实飞05与误识别修正

`latest_visible_20261012_05` 第一阶段通过官方终点变化完成，HUD阶段时长155.168秒。车辆段约23.96米停住，60秒无进度后诊断监测器停止控制，官方比赛完成情况未知。这轮未到达原101分碰车位置，不能证明双目融合已经修好那次碰撞。

用户观察到类似GPS漂移。核对显示控制器仍使用pose_gt；车辆段原始位姿最大单次变化0.04297米，间隔0.012秒，没有发现位置突跳。地图却把车辆橙色面板（约0.77×0.53米、0.80×0.56米）及离道路3.7–4.8米的候选当作可信门，导致错误约束和高度参考。这是感知/参考轨迹问题的直接证据，不能归因于GPS。

继续修正为：左右图均必须存在两侧高白色立柱及橙色门框支持；立体开口必须容纳机体和测量不确定度；车辆段地图横向筛选收紧到3米，对应现有道路2.25米范围和中心开口约0.7米的可达范围。543项测试在主机与ROS容器均通过。修正后是否恢复通行以实飞06结果为准。

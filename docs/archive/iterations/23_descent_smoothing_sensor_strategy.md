# 陡坡俯仰顿挫、穿门抽动与传感器分工

## 已定位的问题

`race_dynamic_07` 首段 s100..650 的速度指令有 7 次在单个采样周期降低超过
0.6m/s，最强约 -15.9m/s²，全部来自 `CROSS_TRACK`。普通跟踪误差被写入
硬上限，绕过了普通减速的 5m/s² 限制；实际飞机尚未减速，高度前馈却已按
新的低速命令计算，容易反复修正高度、速度与俯仰。

当前已有 3.5s、20–50m 坡度预览，并非没有预测。但这种临时硬修正打断了
前视规划的速度曲线。在线门位置更新还会立即替换横向路径，即使当前
位置连续，当前和未来方向也可能突然改变。

## 修改

- 普通横向/高度跟踪限制改为软限制；动态模式速度加速度变化率上限 20m/s³，
  普通加速/减速仍分别受 4/5m/s² 限制。几何硬限速、障碍停机和数据失效
  可立即覆盖平滑，不能为舒适性拖延紧急制动。
- `MotionEstimator` 对实际世界速度做 .12s 滤波，并投影到道路切向。
  动态模式的高度前馈和短响应前视使用实际前进速度，侧移速度不产生虚假的
  坡度前馈。垂直速度预估也采用滤波值。
- 横向门引导复用 `ProfileBlender`，门位置更新在 .4s 内连续衔接；
  值和方向在切换起点不跳变，连续更新时保留当前混合状态。
- 增加官方原点的独立起飞阶段，再以离地位姿建立路线高度初值。
  只在原点附近尚未初始化时生效，车旁停车不得触发这个起飞例外。

166 项回归通过，包含普通跟踪不得绕过减速、普通速度变化的 jerk 上限、
紧急停机不受平滑拖延、侧移不产生高度前馈和门引导切换的方向连续性。

## 传感器策略

当前汽车 YOLO 已训练并用于车辆分类、门误检过滤和双目汽车前脸观测；
近距离绕行一直由 LiDAR 点云检查主导。IMU/位姿用于稳定与时间对齐，
不能直接探测前方汽车。YOLO 检测框也不是完整车身体积或可靠测距。

下一步建议保持以下分工：

1. 远处 YOLO + 双目 + 多帧跟踪做汽车预警和粗定位；视差误差大时只预警。
2. 雷达建立时间对齐的局部三维占据图，短时累积扫描填补车体遮挡；
   对移动目标保留时间信息，不无限累积旧车位。飞机尺寸、定位误差及制动余量
   都进入净空边界，轨迹必须留在门洞和赛道内。
3. 从实际位置、速度生成可执行的连续三维绕行轨迹，包含侧移时间、制动距离、
   加速度和 jerk 约束。现有单帧“先侧移再沿平移路径”仍会发生碰撞，需要继续替换。

平滑速度/加速度/jerk 的原则可参考
[PX4 官方轨迹说明](https://docs.px4.io/main/en/config_mc/mc_jerk_limited_type_trajectory)；
这是设计参考，本项目没有切换成 PX4 飞控。
雷达输出与扫描量程参见
[AirSim LiDAR 文档](https://github.com/Microsoft/AirSim/blob/main/docs/lidar.md)。

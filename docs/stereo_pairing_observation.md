# 双目头时间戳配对与图像年龄（迭代 29，2026-10-23）

继续设计 Sprint C 的输入准备。先前已核对官方 README 与 settings.json；本轮不修改模拟器、插件、碰撞/超时或 RpcEnabled。单独观察器只订阅前视左右 Scene 与正式 IMU，不发布控制、不读取 debug，也未接入飞行循环。P1/P2 均未验收。

实现不可变字节图像解码和有界配对。解码保留原编码与尺寸，支持行填充，拒绝坏布局、未知编码和不合法时间。实际两相机输出为 960×720 bgr8，原 header.frame_id 为空；来源按订阅话题标识，不将该标识当成标定 TF。

IMU 拥有传感器时间，重复 IMU 不刷新 wall deadline，时钟回退或失联终止观察。每侧配对队列最多 4 帧，默认传感器有效期 150ms、接收后 wall 有效期 200ms，头时间差最多 5ms。只从 IMU 已覆盖的有效图像中选取当前最接近的一对，已消费帧不重复使用；队列溢出、过期、旧 epoch、重复/乱序、超前和被较新配对取代的帧分别记录。不是全序列最优匹配或曝光同步证明。

默认 150ms 两次失败均保留，没有用实验模式替换其结果。修订版默认失败场次记录 27 条图像输入，图像到达时头时间戳相对最新收到 IMU 的年龄中位数约 153ms、最大 165ms；进入记录器后等待最大约 1.68ms。原因分类为 SENSOR_EXPIRED，没有记录器 wall 队列过期。该年龄测量无法区分渲染、传输、头时间戳定义或曝光时间，不能据此声称已标定相机延迟。

200ms 是显式只读实验，默认仍为 150ms。两个实验场次所有输出对的左右头时间戳相同，配对时相对 IMU 的年龄中位数约 156/159ms、最大约 189/192ms。首帧左右图像均与 cv_bridge passthrough 解码逐像素一致。输入、输出单独记录，离线审计检查每侧消费时间戳严格递增、IMU 因果覆盖、有效期、限定 skew 和节点订阅。较长预算没有认证运动条件、后续深度推理耗时或制动安全；下游必须重新核对输出新鲜度并使用对应历史位姿补偿。

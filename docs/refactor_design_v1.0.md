# RMUA 2026 鲁棒自主无人机系统完整重构设计

> **版本**：v1.0（技术设计提案）
> **编制日期**：2026-10-19
> **适用范围**：RMUA 2026 六段连续竞赛、动态汽车、线状障碍、持续风、道路外动力衰减、工厂巡检
> **项目策略**：新建 `rmua-next`，原 `RMUA2026-demo` 冻结为可对照的实验基线；不在旧的巨型控制器中继续堆功能。
> **证据口径**：本文将 **[官方已确认]**、**[现有项目]**、**[设计建议]**、**[待核实]** 明确分开。数值型性能目标均为建议验收目标，**不代表当前已经达到**。

## 0. 执行摘要与技术决策

**目标不是“某个种子飞得很快”，而是在未参与调参的随机场景中，依靠比赛允许的传感器，自主完成穿门、避车、抗风、精细穿越和工厂巡检，并有可复现的官方计分证据。**

采用以下主路线：

1. **学习式三维感知**：前后双目深度、门洞几何、动态与细线障碍感知；学习模型输出几何、语义及不确定度，而不直接凭检测框授权高速运动。
2. **有不确定度的世界模型**：统一道路先验、可见自由空间、三维占据、门状态、移动物体预测和状态估计；分清 FREE / OCCUPIED / UNKNOWN。
3. **时空轨迹规划**：全局任务图 + 局部动力学可行轨迹；对车辆预测未来占据，对窄门检查含姿态的机体扫掠体积。
4. **PWM 主控制路线**：优先做可辨识、可验证的四旋翼 SE(3) 级联控制，加入抗饱和、扰动观测和控制余量估计。**VEL 保留为独立场次的对照，不与 PWM 在同一场混发。**
5. **独立安全监督**：检查时间戳、感知覆盖、轨迹可达性、制动安全、力场边界及电机能力；无法证明安全就降低速度、等待、重观测或采用已验证的安全机动。
6. **以数据驱动开发**：用离线回放、批量种子、故障注入和严格留出测试替代“每撞一次就手调一次参数”。

**关键取舍**：本文件确定系统架构与开发顺序；不声称已完成模型选型、PWM 调参或正式服务器的全程验证。

## 1. 比赛任务、评分与不能突破的约束

### 1.1 比赛流程

**[官方规则]** 路线为 `1 → 3 → 5 → 8 → 12 → 10 → 7`，六段分别经过中央枢纽。检测门有触发顺序，只有前一扇成功触发后下一扇才可能得分。排名先按有效检测门数量，再比较时间。后 3 段需完成工厂巡检：`8→12` 有枢纽前工厂，`12→10`、`10→7` 各有枢纽前后工厂；跳过巡检将影响后续门的触发。

每段从起点触发区飞出有 **30 s** 的要求；六段限时依次为 **180 / 180 / 180 / 200 / 220 / 200 s**。工厂 GPS 数据失效（表现为 0），需识别唯一三个灯均为红色的设备，读取 0–50 的仪表整数并正确上报；**错误上报会直接失败**。

沿路有静态线状障碍和悬浮汽车，部分汽车移动；撞到刚性物体即失败。道路与中央枢纽外部有令动力显著衰减的静止力场，累计停留超过 **2 s** 失败；从 8 号点后的室外区域可能出现随机持续风。

> 规则材料：官方模拟器及基础开发仓库；规则条款另见本文末尾的规则文本镜像（非官方原始发布页面，实施前以官方最新规则为准）。

### 1.2 官方公开的模拟器能力

| 接口或资源 | 配置/约束 | 系统用途 |
|---|---|---|
| 前视双目 | 左右 960×720；20 Hz；水平 FOV 60°；基线约 0.30 m | 门洞、远近场景几何、前方障碍 |
| 后视双目 | 同级配置，朝后 | 掉头、后方来车、回程感知 |
| LiDAR | 32 线，10 Hz，200,000 points/s，约 20,000 点/帧，30 m 范围 | 近中距三维占据和净空 |
| IMU | 100 Hz | 高频状态传播、姿态和动力学残差 |
| GPS | 10 Hz；工厂内失效 | 室外定位辅助 |
| 风速计 | 规则标注 50 Hz 世界系真值；模拟器列有 debug/wind 话题 | 风扰分析；**正式使用权限与话题可达性需验证** |
| 初始位姿与当前终点 | 官方 ROS 接口 | 任务初始化与换段 |

### 1.3 开发红线

- 竞赛算法**不得依赖** seed123 预录门表、仿真物体真值或本地调试场景标记；它们可在开发时用于评估、伪标注，但必须与正式算法输入隔离。
- `RouteGeometry` 使用的道路样条可作为**地图先验候选**；需要核实其来源、精度以及规则是否允许在部署包中预置，**不是官方实时 ROS 道路接口**。
- 禁止在一场比赛里同时发布 PWM 和 VEL 来“热切换”；使用不同运行实例进行对照。
- 最终得分、换段、工厂上报成功情况必须以**官方反馈/可确认任务事件**为准，不能拿本地 Gate PASS 账本冒充官方成绩。
- 本地 `IgnoreAllHitCollision` / `IgnoreOverTime` 只能用于开发采样；正式验收必须恢复真实规则。

## 3. 目标系统总体架构

```text
                            Mission Manager
                  六段竞赛 + 门序 + 工厂 + 官方状态
                                  │
         ┌────────────────────────┴────────────────────┐
         │                                             │
  State Estimation                              Perception Pipeline
  IMU/GPS/VIO/LIO                               Stereo/Depth/Gate/Line
  pose, velocity, covariance                    LiDAR/Object/Optical Flow
         │                                             │
         └───────────────────┬─────────────────────────┘
                             ▼
                       World Model
         Route prior | FREE/OCCUPIED/UNKNOWN | gate landmarks
         dynamic obstacle trajectories | uncertainty | timestamps
                             │
          ┌──────────────────┴──────────────────┐
          ▼                                     ▼
   Global Task Planner                     Local Planner
   road / factory graph                time-aware 3D trajectory
          └──────────────────┬──────────────────┘
                             ▼
                    Trajectory Validator
              reachability + clearance + braking
                             ▼
                    Trajectory Controller
                  p/v/a/yaw references
                             ▼
             SE(3) Controller + Disturbance Observer
                             ▼
                 Motor Allocator + PWM Publisher
                             ▼
                         Simulator

    Safety Supervisor 独立监控所有上述阶段，拥有最终否决权。
```

### 3.1 进程/模块隔离

- **感知**采用异步队列（容量 1 的最新帧邮箱 + 可回放原始记录），不允许 GPU 推理阻塞姿态控制。
- **估计与飞控**运行在 CPU 优先级更高的独立执行链；所有环节监控 deadline、CPU/GPU 占用和数据到达延迟。
- **规划**只读取不可变 `WorldSnapshot`，不能在使用过程中被其他线程原地修改；轨迹发布后仍需独立校验。
- **唯一控制发布者**向 ROS 下发 PWM；任何测试或调试节点都不得偷偷发布第二组控制指令。
- 各数据包必须携带：`stamp`、`frame_id`、`valid_until`、`source`、`generation/epoch`、`covariance_or_bounds`。

### 3.2 关键接口（示例）

```python
@dataclass(frozen=True)
class StateEstimate:
    stamp: float
    position_ned: Vec3
    velocity_ned: Vec3
    orientation: Quaternion
    angular_velocity_body: Vec3
    covariance: Matrix
    health: str                  # OK / DEGRADED / LOST

@dataclass(frozen=True)
class GateLandmark:
    track_id: str
    center_ned: Vec3
    plane_normal_ned: Vec3
    aperture_polygon: Polygon3D
    covariance: Matrix
    observed_stamp: float
    status: str                  # CANDIDATE / TRACKED / VERIFIED / LOST

@dataclass(frozen=True)
class WorldSnapshot:
    stamp: float
    epoch: int
    state: StateEstimate
    occupancy: Occupancy3D      # FREE / OCCUPIED / UNKNOWN
    gates: tuple[GateLandmark, ...]
    dynamic_tracks: tuple[DynamicTrack, ...]
    observation_horizon: float

@dataclass(frozen=True)
class Trajectory:
    stamp: float
    valid_until: float
    pva_yaw_samples: tuple      # pos/vel/acc/yaw (+可选角速度/推力)
    safety_certificate: dict
```

上面是**接口草案**，不是可执行源码；真正实现需统一 ROS 消息、自定义类型及跨进程序列化方式。

## 4. 状态估计与定位（包括工厂 GPS 失效）

**目标**：从初始化之后，用正式允许的机载传感器持续估计完整 6DoF 姿态、位置、速度、偏置与不确定度。

1. **基础传播**：IMU 100 Hz 进行姿态/速度预测，ESKF 估计零偏与协方差。
2. **室外更新**：利用 GPS 位置/姿态测量，做异常值检测和融合；初始化位姿只用于合法初始化。
3. **室内/遮挡更新**：引入双目 VIO，并探索 LiDAR-IMU 里程计；使用可观测性、特征数量、创新统计来判断退化。
4. **GPS 突然变零**：不能当作“飞机回到原点”；必须检测为工厂 GPS 无效并拒绝融合，防止滤波器发散。
5. **坐标约束**：世界使用 NED（Z 向下为正）；机体系/相机系/LiDAR 系统一 TF 与标定版本；所有动力学公式必须明确重力和推力的符号。
6. **定位质量**：状态估计输出健康等级。DEGRADED 时下调规划时域和速度；LOST 时停止继续执行未经验证的穿门轨迹，转入经过仿真验收的安全机动。

**禁止**把 `/airsim_node/drone_1/debug/pose_gt` 作为正式运行主状态源，除非获得明确官方允许；可仅用作本地误差统计的隐藏评测真值。

## 5. 学习式三维感知：不再让 YOLO 负责整个导航问题

### 5.1 为什么不能只换一个检测器

检测框是二维目标位置，不是门洞可通行几何，更不是安全轨迹。高速飞行至少需要：三维距离、门平面与净空、遮挡与未知区域、障碍物运动、估计不确定度、观测延迟。

### 5.2 推荐感知任务及输出

| 分支 | 模型/方法候选 | 输出 | 使用方式 |
|---|---|---|---|
| 双目深度 | Fast-FoundationStereo、轻量双目方法、传统 SGBM 基线 | disparity/depth + invalid mask + uncertainty | 局部重建，不能无限信任远距深度 |
| 门洞理解 | 小型语义分割 + 关键点/边界检测 + 三维平面拟合 | 可通行多边形、法向、可信度 | 在线生成 GateLandmark |
| 动态物体 | 语义分割/检测 + 点簇关联 + 光流/场景流 | 目标位置、大小、速度分布 | 时空占据预测 |
| 细线/细杆 | 高分辨率线特征 + 专项分割 + 时序融合 | 不确定的线/柱几何 | 对薄弱观测施加谨慎约束 |
| 工厂视觉 | 红灯设备检索 + 表盘分割/读数 | 目标设备、表读数概率 | 多视角复核后才上报 |

**模型候选不是最终结论。** Fast-FoundationStereo 官方在 RTX 3090、640×480 的 TensorRT 推理报告约 14–23 ms（依模型和迭代数），但这不包括整个 ROS 图像处理链、实际 960×720 输入、LiDAR 融合或模拟器抢占 GPU 的开销。必须进行整链路实测。

### 5.3 双目远距离不确定度

双目几何：`Z=fB/d`，`σ_Z ≈ (Z²/(fB))·σ_d`。以 960 像素宽、60° FOV、0.30 m 基线估算，`f≈831 px`；30 m 处视差约 8.3 px，60 m 处约 4.2 px。远处很小的视差误差也可能引起大的深度误差。

因此：**远距离视觉可以触发提前减速、持续跟踪和风险预测，但除非有足够置信度与独立验证，不能把“看起来没有障碍”当成 100 m 自由空间证据。**

### 5.4 数据集与训练策略

- 从多种子模拟器记录同步双目、LiDAR、IMU、运动状态、时间戳；开发用评测真值**不进入推理输入**。
- 以官方已允许的输入构建可重放数据集；离线伪标注可使用强教师模型、LiDAR 投影和人工复核，但区分标签来源。
- 划分 `train/validation/test-held-out-seeds`；种子不能跨集合泄漏，单次轨迹相邻帧也不能同时进入训练与测试。
- 专项增强：反光玻璃、橙色面板误检、遮挡、夜暗曝光、运动模糊、门框单侧可见、细线、近距来车、远距小门。
- 指标：门洞 3D 中心/法向误差、净空保守误差、深度误差随距离曲线、细线漏检率、来车轨迹预测校准、端到端 P95 延迟。

## 6. 世界模型与在线门图

### 6.1 三态占据与时间一致性

对空间每个体素维护 `FREE / OCCUPIED / UNKNOWN`、观测时间、位置不确定度；视锥外、遮挡后方、过期区域一律不能直接变成 FREE。LiDAR 点云要做时间补偿，必要时用相机深度补齐盲区。动态对象占据由轨迹分布在未来时刻生成，不混成永久静态地图。

### 6.2 在线门建图取代种子门表

- 从左右图识别门边缘和角点，匹配得到 3D 角点或可靠的边界点云。
- 拟合门中心、平面法向、可通行多边形；考虑机体/旋翼包络和测量协方差收缩安全通道。
- 以多帧时空跟踪管理门：候选 → 连续确认 → 可穿越 → 已经过门/失联；不能以单帧框直接建立硬锚点。
- **正确穿越的条件是机体扫掠空间通过门平面且处于安全孔径内**，并用官方事件确认实际得分；本地账本只作估计与调试。
- 原始道路 Spline 只决定搜索区域/方向，不能“证明某扇门已存在或打开”。
- 对未知门：先看、再接近、确认孔径后穿越；尚无可靠测量时进入搜索/谨慎航行模式。

### 6.3 在线高度走廊

从道路几何趋势、可信门三维中心、上下边界点云建立随路线进度的 `z_min(s), z_max(s)` 可行区间，在其中选平滑、动力学可达的 `z_ref(s)`。不要将 Spline 原始 Z 直接当飞行高度；也不要将一个种子的离线 Guide 当运行时真值。

## 7. 动态车辆：时空预测与避让

1. **检测与关联**：由 LiDAR 点簇、双目深度和语义共同提供观测；无需知道类别也要对真实占据进行碰撞检查。
2. **状态预测**：`p,v,a,shape,covariance`；先用 CV/Kalman 基线，再对加减速/转向采用多模型预测（如 IMM）与多假设关联。
3. **占据外推**：为每个未来时间点构造带协方差膨胀的车辆空间；检测丢失时增大不确定度，不能瞬间清除风险。
4. **轨迹决策**：从绕过、减速、等待、跟随、选择确认过的另一侧空间中挑选可达轨迹；不给未观测空间随意分配通行权。
5. **高速验证**：迎面、横穿、从后方追来、两车交会、突然遮挡、车辆停走、静动误分类与 ID 切换。

**设计约束**：每条轨迹要满足机体扫掠体积 `B_drone(t)` 与动态障碍保守占据 `O_i(t)` 不相交，并验证最坏感知延迟与控制响应余量。这是碰撞风险约束，不是仅凭类别框规避。

## 8. 风扰、动力衰减与控制能力监测

### 8.1 持续风扰

建立四旋翼平动与转动模型，保留空气动力扰动项：

`m v_dot = m g + F_thrust(R, u) + F_disturbance`

`J omega_dot = tau(u) - omega × (J omega) + tau_disturbance`

优先实现基于模型残差的扰动观测器/ESO，之后才评估是否使用学习式风扰估计器。估计的扰动用于速度/位置控制补偿，估计方差同时影响规划速度。风速计若被正式允许，可作为观测辅助而非唯一安全来源。

### 8.2 静止力场：不是普通风

道路/枢纽之外的动力衰减应建模为**可用控制能力变化**，不能简单补偿为外力。建立 `ControlAuthorityMonitor`：持续比较预计推力与 IMU/速度响应，估计推力余量、姿态控制余量及异常响应。规划器将已知道路边界视为硬约束，**不能靠进入力场后再补救**；结合规则统计风险暴露时间，避免接近累计 2 s 的失败条件。

### 8.3 推力饱和与失效

设计抗积分饱和、加速度限制、姿态角限制、推力分配约束及饱和时的降级轨迹。若电机饱和导致轨迹不可达，应先缩小运动目标或采用可行回退策略，不能无限增加 PID 增益。

## 9. 近场精细避障：门框、细线、杆、低净空

> 这里将“精细臂避障”理解为**精细近场避障**，覆盖细线、杆件、门框与狭窄通道。若另指机械臂或附加装置，官方四旋翼配置未表明存在该设备，应另行定义几何与动力学模型。

- **门框**：几何由孔径多边形、平面法向与机体姿态共同决定；必须计算旋翼外廓的动态净空。
- **细线/细杆**：专门的线检测、两目匹配、时间融合和不确定度；不能指望 32 线 LiDAR 每次都打到线。
- **低净空**：实时天花板、地板与机体包络距离；姿态倾斜会改变最大外廓尺寸。
- **局部策略**：感知不足时减速/调整视角；按真实净空选择穿门速度；要求规划轨迹在整段时间内有正安全裕度。
- **保护机制**：如果线未被检测，不代表它不存在；已知狭窄区域要提高观测要求，并限制不安全的高速穿越。

## 10. PWM 飞控作为主路线，VEL 作为对照

### 10.1 选择理由与前提

VEL 便于快速验证导航，官方基础飞控可以提供速度指令到电机的转换，但在急剧速度变化时可能有姿态波动。PWM 允许自研姿态、角速度、推力分配和扰动抑制，适合追求高动态性能；代价是我们必须自己保证起飞、稳定悬停、急转、抗风、饱和恢复与安全落地/制动。

**先固定控制接口：每场首次接受的 PWM/VEL 信号会决定该场控制类型。** 单独建立两个 launch 和实验配置，避免混发。

### 10.2 建议的控制链

`Planner(p,v,a,yaw) → Position/Velocity Loop → Desired Thrust/Attitude → SE(3) Attitude & Rate Loop → Mixer → four PWM`。

- 高频由 IMU 更新；中频位置环使用有协方差的状态估计。
- 用官方质量、惯量、电机系数建立初始模型，但必须核实系数单位、PWM 到电机转速/推力映射、电机阶跃响应与混控旋翼方向。
- 官方旋翼编号为 `0 右前、1 左后、2 左前、3 右后`；混控矩阵必须经单轴试验确认正负号，严禁照搬其他飞控的 X 型电机顺序。
- 做抗饱和与故障指令监测；**PWM 全零不是安全悬停指令**。
- 需要明确可执行的紧急减速/定点/复位控制，而不是只生成 `stop=True` 标志。

### 10.3 PWM 验收阶梯

1. 机体参数和混控方向核验；电机单路响应/映射校准（离线与仿真安全环境）。
2. 低风险悬停；姿态与角速度阶跃，记录振荡和饱和。
3. 低速直线、升降、转弯和姿态切换。
4. 风场与动力退化场景的响应与恢复。
5. 与独立 VEL 场次比较同一路线的位置误差、峰值姿态、实际制动距离和故障率。
6. 通过以上门槛之后，逐步提升轨迹规划的加速度和速度，不因 PWM 理论上更强就盲目冲高速。

## 11. 时空规划、速度包络与安全认证

### 11.1 两层规划

- **任务层**：结合官方终点和道路拓扑确定去向、门序与工厂停靠点；不能根据预测的门地图提前“虚构完成任务”。
- **局部轨迹层**：在滚动三维占据和车辆预测中优化有限时域轨迹，约束位置、速度、加速度、姿态、推力/角速度、道路边界、门孔径和障碍风险。

可先用确定性安全走廊 + 多项式/采样候选轨迹做基线，再引入带动力学的 NMPC；不必第一天就部署复杂的全非线性求解器。轨迹控制和估计链稳定前，MPC 的复杂度收益无法验证。

### 11.2 速度必须由可观测距离决定

简化停止距离：

`d_stop ≥ v·tau_total + v²/(2·a_brake_verified) + d_margin`

其中 `tau_total` 含传感器采样、曝光、推理、规划、控制及执行延迟，`a_brake_verified` 是受姿态、风扰和控制能力限制的**实测有效减速度下界**，不能直接拿 VEL 的指令加速度上限当真值。

例如仅作数量级展示：`v=40 m/s, tau_total=0.35 s, a=8 m/s²` 时，理想需求约 `114 m + 安全余量`，已经远大于 30 m LiDAR 范围。相机的远距线索不能自动等价于可证明无障碍的自由空间。因此 **40 m/s 只能作为特定已验证开放路段的候选目标，绝不是默认巡航速度**。

### 11.3 独立安全监督

每次轨迹接受与 PWM 发布前检查：

- 状态/点云/视觉/对象跟踪数据是否过期，时间戳是否单调且属于当前 reset epoch。
- 是否存在未知或未覆盖但即将进入的空间；已确认净空能否支持当前速度和停止动作。
- 是否违反道路/力场边界、门洞几何约束、动态风险约束、推力与姿态限制。
- 当高层规划超时，执行器是否仍在已认证轨迹的有效期内；过期后切换到**经过闭环验证**的低风险策略。
- 单一发布者、控制 deadline、PWM 范围、指令序列号、指令记录是否一致。

在控制余量不足时没有万能的“立即刹停”；安全策略要在风险出现前留出动力学裕度，且在仿真中证明其实际可行性。

## 12. 工厂巡检完整预留（不能等前 3 段完成后才设计接口）

任务状态：`APPROACH_FACTORY → ENTER → GPS_DENIED_LOCALIZE → SEARCH_RED_DEVICE → ALIGN_METER → READ_AND_VERIFY → REPORT → CONFIRM → EXIT → RESUME_ROUTE`。

- 地图与定位：工厂内可能重复纹理、空间受限和 GPS 失效；需融合 IMU、双目/VIO、LiDAR 几何。保证进出口的连续定位和局部地图缓存。
- 搜索：记录已查看区域和仍未知区域，避免 20 个设备反复无序检查；只把三个指示灯都满足条件的设备认定为候选。
- 表盘：透视校正、指针/刻度几何识别，输出整数分布而非只有单一猜测值；多视角/多帧一致后再报。
- 上报：使用 `/airsim_node/meter_report`，依路径位置传 `index=0/1`；检查服务响应、重试语义和是否允许重复提交，错误读数不得冒险上报。
- 检测失败：优先重新观察或重新定位；不能为了节省时间随机猜测，因为错误直接导致失败。

## 13. 运行频率与实时性预算（初始目标，非实测）

| 模块 | 建议频率/方式 | 重要约束 |
|---|---|---|
| IMU 传播与 PWM 发布 | 100 Hz | 按官方最大输入频率设计；抖动和超时必须记录 |
| 状态融合、位置/姿态控制 | 50–100 Hz | CPU 优先链，不等待神经网络 |
| 双目深度 / 门几何 | 尽力 10–20 Hz | 用最新有效帧，输出真实时间戳与置信度 |
| LiDAR 更新 | 10 Hz | 时间补偿、有效范围 30 m |
| 动态障碍预测 | 20–50 Hz | 可在观测之间外推，不代表观测频率提高 |
| 局部轨迹重规划 | 10–30 Hz | 根据最坏计算时间和轨迹有效期调度 |
| 安全看门狗 | 跟随控制发布周期 | 不可被推理/日志 IO 阻塞 |

必须记录总延迟 `t_actuation - t_capture` 的 P50/P95/P99，而不只记录模型 GPU 推理时间。模拟器与网络争用资源时，还要记录掉帧、时钟漂移、任务排队及 CPU/GPU 峰值。

## 15. 分阶段实施计划与客观退出门槛

| 阶段 | 交付物 | 进入下一阶段的门槛 |
|---|---|---|
| **P0 官方接口审计** | 真正可用话题/类型/频率、控制互斥、标定与基线 Docker | 以最小正式允许输入跑通 ROS 通信，确认 PWM 消息与单位 |
| **P1 PWM 基础闭环** | 控制器、混控标定、抗饱和、故障日志 | 悬停/低速/阶跃/延迟/失联场景闭环稳定；独立 VEL 对照 |
| **P2 定位与三维感知** | ESKF + 在线深度 + 门几何 + 3 态地图 | 测试种子上几何误差、时延和定位退化达到预设阈值 |
| **P3 在线穿门** | 无 seed123 静态门表的门搜索与安全穿越 | 至少在多个未参与调参的种子中低速通过 1→3，官方得分有效 |
| **P4 车辆/线障/风** | 动态预测、精细几何、扰动与能力监测、局部规划 | 迎面/横穿/遮挡/线障/持续风等无严重未解释碰撞；有正确安全回退 |
| **P5 前三段连续** | 1→3→5→8 连续换段 | 留出种子批测，记录正式门数、碰撞率和用时，不依赖人工干预 |
| **P6 工厂和后三段** | GPS 失效定位、红灯检索、表读数、上报 | 六段任务完整实现，错误上报为零（在足够样本中检验） |
| **P7 性能优化** | TensorRT、轨迹约束、飞控调优 | 稳定性与官方得分不下降的前提下，再逐段提升速度 |

不把“某个阶段成功一次”当成通过。应事先冻结评测种子集合，保留不可见的测试种子，明确失败类型统计。

### 15.1 建议验收指标

- **任务指标**：官方有效门数、成功换段数、工厂正确上报数、完整比赛完成率、官方耗时。
- **安全指标**：刚性碰撞率、力场累计超时率、最小真实净空、最低控制余量、失联后风险演化。
- **感知指标**：门几何误差、门关联错配率、细线漏检率、占据未知误判为空率、预测概率校准。
- **控制指标**：姿态/位置跟踪 RMSE、峰值超调、实际制动距离、饱和占比、指令 P99 延迟。
- **稳健性指标**：跨种子分布、传感器异常/时钟回退/单帧假阳性/短时相机与 LiDAR 失效后的恢复率。

具体阈值需在 P0/P1 真实测得性能边界后确定；不凭空指定“40 m/s 必过”“99.9% 无碰撞”等无法支持的承诺。

### 15.2 回归测试矩阵

1. 固定种子重复：排除重放不可复现与隐藏状态影响。
2. 未见种子测试：地图布局、障碍数量/位置、车辆速度/方向、不同工厂与风条件。
3. 故障注入：GPS=0、IMU 时间回退、图像掉帧、点云过期、GPU 推理卡住、PWM 发布超时、障碍 track 丢失。
4. 对抗场景：橙色车面被误识别为门、细线漏采、门框半遮挡、多辆车交会、工厂仪表视角差。
5. Docker 提交模拟：无 GUI、镜像大小限制、启动 30 秒、不给环境额外 debug topic、没有人工终端。

## 19. 最终结论

**新项目必须首先能安全、可解释、可复现地飞行，然后才谈极限速度。**

PWM 是合理的主飞控方向，但 PWM 不是安全保证；深度学习是感知升级的关键，但任何模型都不能突破有限探测距离与动力学制动约束。车辆、风扰、力场和精细障碍不是后补功能，而要从第一天就出现在数据接口、世界模型、轨迹规划和安全评测中。六段竞赛还必须完整覆盖 GPS 失效工厂与正确上报任务。

**第一份应交付的可运行成果**：官方接口审计 + 独立 PWM 安全悬停/低速轨迹闭环 + 多种子自动实验记录。然后实现“不依赖 seed123 门表的 1→3 在线穿门”，以此为下一阶段的工程基线。

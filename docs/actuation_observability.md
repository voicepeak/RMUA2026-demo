# 执行器观测边界

2026-10-20 的本地 12.0.0.5 单周期集体 PWM 实验表明，不能把 `debug/rotor_pwm` 当作每条消息时间戳对应的瞬时电机输入。其消息时间戳间隔中位数约 9ms，而值更换间隔中位数约 51ms。0.4 和 0 脉冲可完全不出现在该记录中；另一场 1 脉冲的线上指令仅持续约 9ms，debug 值却在之后约 39ms 的多个样本中保持 1，此时 IMU 比力已经恢复到接近悬停。

因此，撤回早期证据中“debug 电机实际输出平稳，所以不存在实际输入跃变”的推断。真实角速度突增仍由 IMU 和独立姿态记录确认，但这些数据尚不能确定其来源。原始运行文件与数值保留；受影响的历史证据 JSON 已追加解释更正。

| 记录 | 已验证的用途 | 尚不能证明 |
|---|---|---|
| 控制器指令日志 | 本地计算与发布调用的参数 | ROS 线上内容或电机实际消费 |
| 独立 ROS PWM 订阅记录 | 时间戳及 float32 载荷与发送日志逐条匹配 | 后端实际消费时间与电机推力 |
| debug PWM | 本机可解码，部分较慢变化可见 | 瞬时施加 PWM、快速故障不存在、值的精确采样时刻 |
| IMU / 独立姿态 | 本机运动与比力响应 | 冲击一定来自碰撞、风或特定电机 |

独立订阅记录与控制算法隔离。启动时同时确认 IMU 提供者属于 PWM 后端订阅者，并等待包含该后端在内的预期连接；新增诊断读者不会替代模拟器连接。算法实际输入仍只有 initial_pose、IMU、GPS。

rospy 的 `serialize_message` 会重写 Header.seq。审计以相同时间戳和逐位一致的 float32 载荷推导一个固定序号偏移，再检查所有消息；缺失、重复、额外消息或载荷差异均使审计失败。旧版不可变镜像只允许一个订阅连接，新 harness 默认不为它们开启 PWM 指令订阅；新兼容镜像可显式使用 `--record-pwm-commands`。

0、0.4、0.6、1 的单条集体激励均有本地飞行记录，0 和 1 已在线上逐位确认并出现相应 IMU 响应。这不构成稳态满量程推力曲线、正式服务器权限或持续失联回退验收。正常混控上限仍为 0.6，`full_range_verified` 仍为 false。

`physics_residual.py` 优先读取独立 ROS 指令；历史文件缺少线上记录时显式标记 debug 来源未核实。其模型未包含经验证的消费时延和执行器动态，残差仅用于定位时间窗口，不用于证明接触原因或认证控制能力。

机器可读契约：`configs/evaluation_contracts.json`。运行、失败、重新分析版本与匹配计数：`docs/evidence/p0_pwm_wire_observability.json`。

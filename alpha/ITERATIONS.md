# 迭代流程（Alpha）· 详细版

> 本文是 Alpha 的"怎么走"手册：每一轮怎么定义、怎么做、怎么判定、怎么记录。
> 读者：项目负责人（人）与执行者（AI/工程师）。所有条目都必须可检查、可复现。

---

## 0. 一分钟看懂

- 我们只有一个 KPI：**得分表**（完成阶段数、分数、用时、失败原因）。
- 每轮迭代 = **一个假设 + 一个最小实验（默认 3 场、≤30 分钟）+ 得分表变化 + 一句结论**。
- 每轮只有一个变量；失败必须归因（代码/环境/参数），不允许"重跑一下过了"掩盖问题。
- 每轮开始打 tag，失败直接回滚；不是"尽量"，是纪律。

---

## 1. 术语与约定

| 术语 | 含义 |
|---|---|
| seed | 官方模拟器场景参数（`run_simulator.sh <seed>`），不同 seed 对应不同配置 |
| 场 / run | 一次从起飞到结束（或失败）的完整实验 |
| 轮 / iter | 一个迭代（假设→实验→判定→记录） |
| 阶段 stage | 官方赛程段（1→3→5→8…，以 `end_goal` 变化/官方事件为准） |
| 得分表 | `alpha/scoreboard.jsonl`，每场追加一行 |
| 冻结 | 阶段结束时的固定配置回归，3 场全跑 |

**固定开发集**：`123 / 456 / 789 / 42 / 2026`。
每轮至少跑 `123`，其余轮流覆盖；留出种子（未参与调参）只在 P5/赛前使用。

## 2. 迭代循环（详细五步）

### 第 1 步：看（5 分钟）
- 打开 `scoreboard.jsonl` 最后 10 行
- 找**最大损失**：按 `stage` 从低到高、再按 `fail` 计数排
- 例：最近 10 行里 7 行失败在 `gate4_det`，下一步就做门 4 检测

### 第 2 步：写假设（1 句话）
格式：**"如果 <改动>，那么 <可观测指标> 会 <变好/恢复>，因为 <原因>。"**
例："如果给门检测加自适应 ROI（按状态预测裁剪），那么 8m 外门 4 的检出率会从 60% 提到 90%，因为远门缩图后角点丢失。"
- 假设必须可证伪：实验跑完能明确判"对/错"
- 一轮只允许一个变量（参数扫描轮除外）

### 第 3 步：最小实验（≤30 分钟）
- 固定：seed、配置、代码 commit、sim 版本、容器
- 默认 3 场（成功率是概率量，1 场没有统计意义；3 场是底线）
- 立即失败（起不来/崩溃）→ 记 `env`，重跑，最多 2 次
- 实验命令统一走 `./run.sh <seed>`，禁止手敲零散命令

### 第 4 步：判定（5 分钟）
对比基线的顺序：**阶段数 > 分数 > 用时**（阶段数相同才看分数，分数相同才看用时）。

结论只有三种：
- **保留**：指标变好或持平且不引入回归 → 提交
- **回滚**：指标变差/回归 → `git revert` 或切换回 tag
- **无效**：指标无统计差异 → 要么加大样本，要么放弃这个假设（记录）

归因规则：

| 类别 | 判据 | 动作 |
|---|---|---|
| 代码 | 可复现的失败/退化 | 改代码，下一轮 |
| 环境 | sim 崩溃、掉帧、角速度异常、清理失败；重跑 ≤2 次通过 | 记 `env`，重跑，不改代码 |
| 参数 | 需要标定/扫描（速度、刹车、阈值） | 单独一轮参数实验，不混合代码改动 |

### 第 5 步：记录（2 分钟）
- `git tag alpha-iter-NN`（每轮开始前打）
- `ITERATIONS.md` 追加一条（模板见第 7 节，≤10 行）
- 视频留在 `runs/<ts>_<seed>/hud.mp4`，不提交

## 3. 得分表字段规范

一行 = 一场：

```json
{"ts":"2026-10-30T12:00:00+08:00","seed":123,"stage":3,"score":0,"time_s":151.4,
 "fail":null,"commit":"abc1234","note":"conservative"}
```

| 字段 | 规则 |
|---|---|
| `stage` | 实际完成到第几段（官方事件/end_goal 变化为准；HUD 数字只作参考） |
| `score` | 官方分数（拿不到官方分时填 0，并在 note 写明） |
| `time_s` | 从起飞到结束/失败的墙钟时间；失败场也记录 |
| `fail` | 枚举：`takeoff / gateN_det / gateN_pnp / gateN_track / crash / timeout / env`；成功填 `null` |
| `note` | `conservative` / `aggressive` / 其他实验标签 |
| `commit` | 该场源码 commit 短哈希（必须真实） |

**比较两轮时的展示**：成功率（成功场/总场）× 平均分数 × 平均用时，三列一起看。

## 4. 产物与目录

```
alpha/
├── run.sh                  # 唯一入口
├── scoreboard.jsonl        # 每场一行（gitignore，不提交）

    └── meta.json           # commit/配置/seed/sim 版本
```

规则：
- 每场必有 `meta.json`（否则该场无效）
- 视频只留最近 20 场，旧的删（磁盘纪律）
- `gates_<seed>.yaml` 一旦用于比赛提交，必须提交到 `configs/` 并冻结

## 5. 阶段细则（P0~P7）

### P0 基建—— 先让"看得见"

**目标**：一条命令跑一场，出视频 + 得分表行。

任务：
1. **仿真起停封装**：核实 main 的 `tools/start_gpu_env.sh`（容器 `rmua_next_gpu`，`RMUA_CONTAINER` 环境变量）与官方 `run_simulator_offscreen.sh <seed>`；封装成 `sim_up.sh <seed>` / `sim_down.sh`，断言清理成功（无残留 ros master/模拟器进程）
2. **录屏 + HUD**：订阅前视相机，叠加状态/目标/门框/速度/阶段文字；每场一个 mp4（ffmpeg 落盘）
3. **得分表**：mission 结束时自动追加一行（字段见第 3 节）
4. **端到端**：`./run.sh 123` 跑通占位 mission（起飞→悬停 5s→降落→记分）

**验证**：`./run.sh 123` 连续 3 次都产出 mp4 + 3 行得分表，清理无残留。
**失败分支**：容器 GPU 不可见 → 检查 nvidia runtime（main 文档有 driver-recovery 记录）；offscreren 模式截图黑屏 → 开渲染模式调试。

### P1 采集建图—— 先回答"门变不变"

**目标**：`gates_<seed>.yaml`（门坐标/法向/尺寸），并用复投影校验；回答"门是否跨 seed 固定"。

任务：
1. **scout 扫描**：debug 配置（`GameConfig.json` 的 `IgnoreAllHitCollision`/`IgnoreOverTime` 仅本地调试）下，用 pose_gt 引导沿赛道飞一圈；同步记录：前视图像、pose_gt、检测到的门
2. **单帧门位姿**：四角 + 已知门尺寸 → PnP → 门相对位姿；剔除斜视角/边缘裁剪
3. **世界坐标**：PnP 相对位姿 + pose_gt → 门在世界系位姿；多帧平均（≥10 帧）
4. **校验**：用记录轨迹把门投影回图像，与分割掩码算 IoU，目标 >0.8
5. **决策实验**：对 seed 123 与 456 各采集一遍，比较门数量/位置/尺寸——**布局一致 → 一张图通用；不一致 → 逐 seed 自动采集**

**验证**：yaml 落盘 + IoU 报告。
**失败分支**：门检测漏门 → 补采（多飞一圈不同高度）；PnP 抖动 → 加 RANSAC + 多帧中值。

### P2 定位

**目标**：GPS(10Hz)+IMU(100Hz) → 位置/速度/姿态，悬停误差 <0.5m。

任务：
1. EKF 骨架（优先复用 main `estimation/imu_gps`，只搬必要部分）
2. 时间基准：IMU 时间戳为全局时钟（官方建议）；处理 GPS 到达延迟
3. 悬停 10s：测位置 RMSE/最大误差
4. 直线 20m：测跟踪与速度误差
5. 保护：陈旧 IMU 拒发、跳变限幅（复用 main 的 safety 逻辑）

**验证**：3 场悬停 + 3 场直线，指标写进得分表 note。
**失败分支**：GPS 跳变 → 加门限/多帧一致；IMU 偏差 → 简单标定（在线零速更新）。

### P3 在线穿门

**目标**：单目角点 → PnP → EKF 融合，连续穿第 1 门 ≥5 次，端到端延迟 <150ms。

任务：
1. YOLO bbox → 四角回归（从 beta 权重出发；必要时用 MonoRaceGate 数据集补充）
2. PnP 在线化：ROI 裁剪（按状态预测）、斜视角拒绝、RANSAC
3. 门序跟踪：ID 关联、丢帧重锁（连续丢失 N 帧 → 减速搜索）
4. 融合：PnP 作为 EKF 观测；视觉异常时以运动模型预测（MonoRace 手法）
5. 延迟测量：图像时间戳 → 指令发出时间，p95 <150ms（超时数据直接丢弃，不硬等）

**验证**：固定 seed 连穿第 1 门 5/5 或 ≥4/5；延迟报告。
**失败分支**：延迟超标 → 降分辨率/ROI/事件触发；角点抖动 → 滤波 + 多帧融合。

### P4 第一段完赛

**目标**：官方 1→3 段切换连续 ≥3 次，用时 ≤151s（beta 历史线）。

任务：
1. 速度剖面：梯形速度 + 刹车距离 = f(实测减速度)
2. 丢门恢复：减速 → 搜索 → 重锁 → 继续；卡死 → 悬停重试（有超时上限）
3. 切段：以 `end_goal` 变化/官方事件确认，不靠 HUD 数字
4. 端到端 3 场（每次全新进程 + 全新场景）

**验证**：3 场中 ≥2 场完成 1→3 切换，平均用时 ≤151s。
**失败分支**：反复丢门 → 回 P3；超时 → 检查速度/刹车参数（单独参数轮）。

### P5 跨种子（1 周）

任务：
1. 空图启动（无预录输入）+ 现场采集或预采集（取决于 P1 决策）
2. 失败归因自动化：视频+遥测 → 自动生成 fail 字段
3. 未调参种子（如 42/2026）各 ≥1 次过第一段
4. 冻结回归：固定集 3 场全跑

### P6 后段任务（1~2 周，可与 P5 并行）

- 动态车辆：检测 → 保守让行/停等（不搞预测规划）
- 线障：贴边通过（保守绕行）
- 工厂：读表（表盘角度候选已存在可复用）+ `meter_report` 上报
- 无 GPS 段：门图推算 + IMU 短时航位推算（必要时再上轻量 VIO）

### P7 竞速优化（赛前 1~2 周）

- racing line（门间直线、出口加速点）
- 速度包络：实测升降/制动能力，替换保守参数
- 双策略：保守/激进两套参数，按成功率选择
- A/B：固定集对比，成功率不得下降

## 6. 回滚与冻结

- 每轮开始：`git tag alpha-iter-NN`
- 判定"回滚"时：`git revert` 对应 commit（保留历史，不 force-push）
- 阶段冻结：固定代码/配置/模型/门图，3 场全跑；冻结期间只修回归失败
- 任何"为通过而放宽安全边界/改官方设置"的改动：禁止

## 9. 无效迭代（做了也不算数）

- 没有假设、只是"试试看"
- 没有跑实验，只改了文档/注释
- 跑了实验但没写得分表
- 比较时混了多个变量
- 用"重跑通过"代替归因
- 改了官方模拟器/计分/安全边界换来的"成绩"
